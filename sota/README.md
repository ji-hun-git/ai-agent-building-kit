# State of the art: building production AI agents

**Verified 2026-10-28.** Package, SDK and spec versions were queried on 2026-10-28; every other row carries the date its source was last opened. For the order in which to adopt these methods, layer by layer, from the template's baseline to the best-performing option, see [the upgrade ladders](ladders.md).

Every row is a snapshot, not a standing recommendation: model lineups, beta headers, preview statuses and leaderboard ranks move within weeks. Run `python skill/building-ai-agents/scripts/check_freshness.py` before relying on a version, then pin exact versions. Each table lists the few entries worth starting from in its area, not everything that exists. The decision rules, caveats and full source lists behind each row are in the skill's `references/` folder. Cost appears only as mechanisms; no prices are listed.

**Legend**

- **volatile**: changes often (lineups, ranks, beta headers, preview or GA status). Re-check at the linked source before use.
- **(unverified)**: the source itself marks the fact as unconfirmed, estimated, second-hand or taken from a secondary source.
- **vendor-reported**: a figure published by the vendor of the product it describes. Measure on your own evals.
- **Verified**: date the source was opened or the version was queried.

**Default pipeline in 6 lines**

1. Parse with a layout-aware parser; add a page-image path for slides, scans and charts.
2. Chunk on structure (sections, whole tables and lists). Store doc id, version, page, ACL fields and a contextual prefix on every chunk.
3. Run BM25 and dense search in parallel, fuse the lists and keep about 150 candidates.
4. Rerank and pass only what clears a calibrated threshold (cap about 20). If nothing clears it, rewrite the query or answer "not found".
5. Expose `search` and `read` tools, filtered inside the engine with the end user's own token, and cite doc id, page and span.
6. In CI, score document-level recall@k separately from faithfulness on 100–200 real, stratified questions. Re-index on change and pin the index version in the release.

Skip retrieval only when the corpus is under about 200K tokens, rarely changes and every user may see all of it. In that case, put it in the prompt with prompt caching.

Class every tool as read, reversible write or irreversible write, and enforce the class in the harness. Reads run without asking. Reversible writes need a policy check, an idempotency key and an audit span. Irreversible or external actions need a dry-run preview and per-call approval that shows the exact arguments. MCP annotations are untrusted hints, and their defaults are pessimistic (not read-only, destructive, not idempotent, open-world). Claude Code users approved 93–97% of permission prompts but rejected 39% of plans, so ask at the plan and at irreversible actions, and let the sandbox and policy handle routine steps. If a sandboxed shell already exists, try a mature CLI before building an MCP server.
